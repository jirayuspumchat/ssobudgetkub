# เข้าใจงบ ประกันสังคม — หน้าเว็บ

หน้าเว็บหน้าเดียวที่อธิบายงบบริหารงานสำนักงานประกันสังคม ปี 2563–2567
สร้างจาก `../dataset/*.csv` ซึ่งสกัดมาจากไฟล์ PDF ราชการใน `../`

## ไฟล์

| ไฟล์ | คืออะไร |
|---|---|
| `index.html` | โครงหน้าและ CSS ทั้งหมด |
| `app.js` | ตรรกะ กราฟ และการโต้ตอบทุกส่วน เขียน SVG เอง ไม่มีไลบรารีภายนอก |
| `build_data.py` | อ่าน CSV แล้วสร้าง `data.js` พร้อมตรวจยอดให้ |
| `data.js` | **ไฟล์ที่ generate มา ห้ามแก้ด้วยมือ** |
| `index.standalone.html` | **ไฟล์ที่ generate มา** รวมทุกอย่างไว้ในไฟล์เดียว ส่งต่อให้คนอื่นเปิดได้เลย |

## เปิดดู

`index.html` ต้องเปิดผ่าน HTTP เพราะโหลด `data.js` กับ `app.js` แบบไฟล์แยก

```bash
python -m http.server 8777 --directory web
```

แล้วเปิด <http://localhost:8777>

ถ้าอยากได้ไฟล์เดียวจบ เปิด `index.standalone.html` ด้วยการดับเบิลคลิกได้เลย
ไม่ต้องมีเซิร์ฟเวอร์ ฟอนต์เป็นไฟล์โลคัลใน `fonts/` แล้ว (ไม่ต้องต่อเน็ต)
แต่ต้องวาง `fonts/`, `logo-light.png`, `logo-dark.png` และ `flashthink-white.png` ไว้ข้าง ๆ ไฟล์เสมอ

## สร้างข้อมูลใหม่เมื่อ dataset เปลี่ยน

```bash
python web/build_data.py --inline
```

สคริปต์จะ **ตรวจยอดให้ก่อนเขียนไฟล์** ถ้าไม่ตรงจะหยุดและไม่เขียนอะไรเลย:

- ผลบวกรายการย่อยสุดของแต่ละปี = ยอดรวมใน `budget_annual_summary.csv`
- ผลบวกแผนงานระดับบนสุด = ยอดรวมรายปี
- ยอดสินทรัพย์รวมตรงกับ `outputs/csv_audit_2026-09-11/report_th.md`
- ราคาที่ได้มา + ค่าเสื่อมสะสม = มูลค่าตามบัญชี

ตัด `--inline` ออกถ้าไม่ต้องการสร้าง `index.standalone.html` ใหม่

## กติกาที่ยึดไว้ตอนอ่านข้อมูล

ถ้าจะแก้ `build_data.py` ต้องรักษาสี่ข้อนี้ไว้ ไม่งั้นตัวเลขทั้งหน้าจะผิด

1. **รวมยอดต้องกรอง `เป็นรายการย่อยสุด == 'ใช่'`** ห้ามใช้ `เป็นแถวสรุป == 'ไม่ใช่'`
   วิธีหลังนับซ้ำเกินจริง 568–794 ล้านบาทต่อปี
2. **ช่องว่างไม่ใช่ศูนย์** — ต้นฉบับพิมพ์ขีดไว้ เก็บเป็น `null` แล้วแสดงเป็น `—`
3. **ห้ามคำนวณ `คงเหลือ` ใหม่** — มี 529 แถวที่ `จัดสรร − เบิกจ่าย ≠ คงเหลือ` ตามต้นฉบับ
4. **`หมวดค่าใช้จ่าย` ชื่อซ้ำข้ามสาขา** — ต้องคีย์ด้วย path เต็ม ไม่ใช่ชื่อเดี่ยว
   (เช่น "ค่าใช้สอย" ปี 2567 โผล่ 4 ครั้งใต้แผนงานคนละอัน)
5. **ห้ามรวมรายการข้ามปีด้วยความคล้ายของชื่อ** — การจับคู่ทั้งชุดใช้
   `ชื่อตรงกันทุกตัวอักษรหลังปรับรูป` เท่านั้น ถ้าจะรวมคู่ที่ชื่อต่างกัน
   ต้องผ่าน `dataset/manual_merge.csv` ซึ่งต้องมีคนตัดสินกำกับ (ดูหัวข้อถัดไป)

## การรวมรายการที่ชื่อต่างกันนิดเดียว

เอกสารต้นฉบับสะกดชื่อรายการเดียวกันไม่ตรงกันข้ามปี เช่น `ปลดดภัย` กับ `ปลอดภัย`
หรือ `KGS` กับ `KTBGS` ทำให้กลายเป็นคนละรหัสกลาง และประวัติย้อนหลังขาดปีไป

**ระบบไม่รวมให้อัตโนมัติ** เพราะบางคู่ที่ชื่อคล้ายกันมากเป็นคนละเรื่องจริง ๆ
(เช่น `โครงการพัฒนาระบบโครงข่าย` กับ `โครงการเช่าระบบโครงข่าย` เหมือนกัน 94.6%)
การรวมผิดจะทำให้ประวัติงบของรายการนั้นผิดไปทั้งเส้น

ขั้นตอน:

```bash
python dataset/scripts/build_merge_candidates.py   # อัปเดตรายชื่อคู่ที่ต้องตัดสิน
# แก้ dataset/manual_merge.csv ด้วยมือ
python web/build_data.py --inline                  # รวมตามคำตัดสิน
```

`build_data.py` จะรวมให้เฉพาะแถวที่ `การตัดสิน == "รวม"` **และ** กรอก `ผู้ตัดสิน` ไว้
แถวที่เว้นว่างถือว่ายังไม่ตัดสิน ไม่รวมให้ และหน้าเว็บจะยังเตือนว่าประวัติอาจไม่ครบปี
หลังรวมแล้ว build จะตรวจว่าผลรวมจัดสรรทุกรายการต้องเท่าเดิม ไม่งั้นหยุดทันที

`build_merge_candidates.py` รันซ้ำได้ คำตัดสินที่กรอกไว้แล้วจะไม่ถูกเขียนทับ

## ดาวน์โหลดข้อมูล (ส่วนที่ 8)

หน้าเว็บสร้างไฟล์ CSV และ JSON **ฝั่งเบราว์เซอร์** จากข้อมูลที่ฝังมากับหน้า
จึงทำงานได้ทั้งตอนเปิดผ่านเซิร์ฟเวอร์ เปิดจากไฟล์ local และใน `index.standalone.html`
โดยไม่ต้องก๊อป `dataset/` ขนาด 150 MB มาไว้ข้าง ๆ

มี 8 ตารางให้โหลดแยก บวกไฟล์รวมก้อนเดียว (~1.7 MB) ทุกไฟล์:

- CSV ใส่ BOM ไว้ข้างหน้า Excel จึงเปิดภาษาไทยได้โดยไม่เพี้ยน
- ค่าว่างคงเป็นช่องว่าง (CSV) และ `null` (JSON) ไม่ถูกเติมเป็นศูนย์
- ไฟล์รวมมีคีย์ `เกี่ยวกับ.ข้อควรระวัง` อธิบายกับดักการอ่านติดไปด้วย

ถ้าจะเพิ่มหรือแก้ตารางที่ให้โหลด แก้ที่ตัวแปร `SETS` ในฟังก์ชัน `downloads()` ของ `app.js`

ทะเบียนสินทรัพย์รายบรรทัด (39 MB) และรายการตรวจสอบเพิ่ม (48 MB)
ใหญ่เกินกว่าจะฝังมากับหน้าเว็บ ส่วนนี้จึงแสดงเป็นพาธให้คัดลอกไปเปิดจากโฟลเดอร์โครงการแทน

## ที่มาของตัวเลข

ตัวเลขบนหน้าเว็บมีสองประเภท และแยกป้ายกำกับไว้คนละแบบ

- **จากชุดข้อมูลนี้** — ติดป้ายเลขหน้าของ PDF ต้นทาง ตรวจย้อนกลับได้
- **บริบทภายนอก** — ป้ายสีทองพร้อมลิงก์ ได้แก่ มูลค่าเงินลงทุนกองทุนประกันสังคม
  และเพดานค่าใช้จ่ายบริหารงานตาม พ.ร.บ.ประกันสังคม พ.ศ. 2533 มาตรา 24
  สองตัวนี้ไม่ได้อยู่ในเอกสารชุดนี้ ถ้าจะแก้ ให้แก้ที่ตัวแปร `EXT` ต้นไฟล์ `app.js`

## ชุดสีกราฟ

ยึด CI ของสำนักงานประกันสังคม (น้ำเงิน `#005C9E` + ทอง `#FFC324`)
ชุดสีกราฟผ่านการตรวจด้วย `validate_palette.js` ของ skill `dataviz` ทั้งโหมดสว่างและมืด
(lightness band / chroma floor / CVD separation / normal-vision floor)
ถ้าจะเปลี่ยนสี ต้องรันตรวจใหม่ ไม่ใช้วิธีกะเอาด้วยตา


## UI/UX การอ่านและแชร์

- ข้อความสรุปใต้แถบเปรียบเทียบคำนวณจากข้อมูลชุดเดียวกับกราฟ และคัดลอกพร้อม URL ของหน้าปัจจุบัน
- ภาพแชร์ `og-image.png` ขนาด 1200 × 630 และ Open Graph ใช้ URL สาธารณะ `https://ssobudgetkub.vercel.app/` ต้องเผยแพร่ภาพไปพร้อม HTML
- แถบความคืบหน้า 3px และสารบัญแสดงบทปัจจุบันทั้ง 8 บท; หน้าจอไม่เกิน 900px ใช้ dialog สารบัญชื่อเต็ม รองรับ Escape และคีย์บอร์ด
- โครงสร้างงบตั้งแต่ความลึก 2 ใช้แท่งแนวนอนและเปิดตารางเป็นค่าเริ่มต้น ผู้ใช้ยังพับตารางเองได้
- ตารางมีเงาด้านขวาเมื่อยังเลื่อนได้ จำกัดความสูงสำหรับหัวตาราง sticky และเลื่อนด้วยคีย์บอร์ดได้
- ปุ่ม # คัดลอกลิงก์บท; โหมดพิมพ์กาง details ซ่อนเมนู ใช้พื้นขาว และคืนธีม/สถานะ details หลังพิมพ์
- แถบปิดท้ายเว็บ (`.sitefoot`) ใช้พื้นสีทึบ `#003f6e` ตายตัวทั้งสองธีม เพราะโลโก้ทั้งสองไฟล์เป็นสีขาวโปร่ง ถ้าผูกกับตัวแปรธีมแล้วสลับเป็นโหมดสว่างโลโก้จะหายไปกับพื้น; ลิงก์ในแถบนี้ใช้ทอง `#ffc324` (คอนทราสต์ 6.7:1) และ `:focus-visible` เปลี่ยนเป็นสีทองด้วย เพราะน้ำเงิน `--brand` มองแทบไม่เห็นบนพื้นนี้
- §8 เป็น `<section class="foot" id="s8">` ไม่ใช่ `<footer>` แล้ว landmark `contentinfo` เหลืออันเดียวคือแถบปิดท้าย ส่วนตัวจับบทใน `app.js` ใช้ `.chapter[id], .foot[id]` จึงยังนับครบ 8 บทเหมือนเดิม
- โหมดพิมพ์ซ่อนโลโก้ในแถบปิดท้าย (สีขาวบนกระดาษขาว) และพิมพ์ URL ต่อท้ายชื่อผลงานก่อนหน้าแทนลิงก์ที่กดไม่ได้
- การเลื่อนใช้ reveal แบบครั้งเดียวพร้อม stagger ตามกลุ่มข้อมูล แท่งกราฟขยายจากซ้าย และ sparkline วาดเส้น โดยลดระยะ/เวลาในมือถือและปิด motion ทั้งหมดเมื่อระบบตั้ง `prefers-reduced-motion: reduce`

ตรวจการใช้งานด้วยเบราว์เซอร์ที่ความกว้าง 375px และ 1280px แล้ว: สารบัญครบ 8 บท, กระโดดบท, สถานะคัดลอก, ไฮไลต์บท, ตารางล้นเฉพาะกรอบ, เลือกปีด้วย Enter และเปลี่ยนกราฟชั้นลึกพร้อมเปิดตาราง ผ่านการตรวจ syntax ด้วย `node --check web/app.js` ด้วย ส่วนหน้าพิมพ์จริงและตัวอย่างแชร์ LINE/Facebook ต้องตรวจหลังเปิดในเบราว์เซอร์ที่รองรับ print preview และเผยแพร่เว็บไซต์แล้ว
